Hướng dẫn

Setup và chạy huấn luyện

Từ lúc quyết định train đến lúc có file kết quả: chọn cách chạy, chỉnh cấu hình cho vừa máy, theo dõi, dừng giữa chừng, train tiếp và chạy nhiều seed để so sánh.

Trước khi bấm chạy

  • Kiểm tra thiết bị: python -c "from pacman_rl import *; print(describe_device(get_device()))" phải ra cuda | ... nếu bạn có GPU.
  • Đóng bớt ứng dụng nặng, nhất là khi train DQN: buffer 1.4 GB và 16 process env cạnh tranh RAM. Tốc độ DQN dao động nhiều theo RAM còn trống.
  • Chọn cỡ n_envs theo máy, xem bên dưới.
  • Biết mình muốn gì: hãy chạy trước bản ngắn 50,000 bước để chắc pipeline ổn rồi mới bỏ hàng giờ cho bản dài.

Train bằng dòng lệnh

# cấu hình mặc định (PPO 2 triệu bước, DQN 10 triệu bước)
python -m pacman_rl train ppo
python -m pacman_rl train dqn

# đổi số bước, seed, tên run, thư mục lưu
python -m pacman_rl train ppo --steps 5000000 --seed 1 --name ppo_s1 --out runs

# ghi đè bất kỳ siêu tham số nào
python -m pacman_rl train ppo --set lr=1e-4 n_envs=8 n_steps=256 c2=0.02

Khi chạy, lệnh in thiết bị và toàn bộ config đang dùng (trừ reward_fn) lên dòng đầu. Đọc dòng này để chắc --set đã có hiệu lực.

Kết quả ghi vào --out (mặc định runs/, tự tạo nếu chưa có), ba file mang tên --name (mặc định ms_pacman_ppo hoặc ms_pacman_dqn):

runs/ms_pacman_ppo.pt             trọng số mạng (state_dict)
runs/ms_pacman_ppo_episodes.npy   mảng (N, 2): (bước env, điểm thật) của từng ván
runs/ms_pacman_ppo_log.npy        dict các chỉ số theo thời gian

Toàn bộ tùy chọn ở Dòng lệnh (CLI).

Trùng tên sẽ ghi đè

Train hai lần cùng --name và --out thì lần sau đè lần trước, không hỏi. Khi thử nhiều cấu hình, luôn đặt --name khác nhau (ví dụ ppo_lr1e4_s0).

Train bằng Python

from pacman_rl import PPOConfig, train_ppo, save_run, get_device

device = get_device()
cfg = PPOConfig(total_steps=2_000_000, lr=2.5e-4, seed=0)
result = train_ppo(cfg, save_path="runs/ppo.pt", device=device)   # TrainResult(model, log, episodes)
save_run(result, "runs", "ppo")                                    # ghi 3 file

train_ppo và train_dqn nhận cùng bộ tham số chạy. Các tham số này không nằm trong Config vì chúng không làm thay đổi kết quả học:

Tham sốMặc địnhÝ nghĩa
cfgNonePPOConfig / DQNConfig. Bỏ trống thì dùng mặc định.
modelNoneMạng có sẵn để train tiếp. None thì tạo mới. Xem Train tiếp.
save_pathNoneĐường dẫn .pt để lưu checkpoint giữa chừng và khi xong. None thì không lưu file nào.
deviceNonetorch.device. None thì get_device() tự chọn.
renderFalseTrue: env số 0 mở cửa sổ, tất cả env chạy tuần tự (chậm).
watch_every0Cứ mỗi bấy nhiêu bước env, dừng train và mở cửa sổ cho agent chơi. 0 là tắt.
watch_episodes1Số ván mỗi lần xem.

Script .py trên Windows

Đặt lệnh train trong khối bảo vệ, nếu không các process env sẽ import lại script và gọi train đệ quy:

def main():
    ...

if __name__ == "__main__":
    main()

Trong Jupyter không cần. Ngoài ra, log có tiếng Việt nên console Windows mặc định (cp1252) sẽ báo UnicodeEncodeError khi chạy script riêng; chạy bằng python -X utf8 script.py hoặc đặt PYTHONUTF8=1. Dòng lệnh python -m pacman_rl tự xử lý việc này. Xem Xử lý sự cố.

Theo dõi trong lúc train

Dòng log

PPO in một dòng mỗi log_every update; DQN in mỗi log_every bước env (đơn vị khác nhau, xem đơn vị). Dấu hiệu run khỏe:

  • steps/s ổn định sau vài chục giây đầu (nếu tụt dần có thể RAM đang thiếu).
  • avg score(20) có xu hướng tăng theo thời gian (dao động vài chục điểm giữa hai dòng là bình thường).
  • entropy (PPO) giảm từ ≈ 2.2 xuống dần, không sụp đột ngột về gần 0.
  • Q (DQN) tăng chậm và không phát nổ.

Cách đọc chi tiết từng chỉ số: Vẽ biểu đồ, đọc log.

Xem agent chơi

python -m pacman_rl train ppo --watch-every 500000   # mỗi 500k bước mở 1 ván

Train tạm dừng trong lúc ván đó chạy (cần có màn hình). --render thì khác: nó mở cửa sổ ngay trên env đang train nhưng làm cả quá trình chậm hẳn, chỉ nên dùng để kiểm tra nhanh.

Dừng giữa chừng và checkpoint

  • Ctrl+C (hoặc nút Stop trong notebook) là cách dừng an toàn: hàm bắt KeyboardInterrupt, đóng các env, lưu .pt và trả về phần đã train. CLI sau đó vẫn lưu đủ 3 file.
  • Checkpoint tự động chỉ có .pt: PPO mỗi save_every update (mặc định 200), DQN mỗi save_every bước env (mặc định 500,000). Cần có save_path.
  • _episodes.npy và _log.npy chỉ được ghi khi hàm train kết thúc (kể cả khi Ctrl+C). Nếu máy sập hay process bị giết đột ngột, bạn chỉ còn .pt checkpoint gần nhất.

Chạy rất dài?

Đặt save_every nhỏ để mất ít nhất nếu máy treo. Với PPO mặc định, 200 update ≈ 410,000 bước.

Train tiếp từ model có sẵn

from pacman_rl import PPOConfig, train_ppo, load_run, get_device

device = get_device()
old = load_run("runs", "ppo", "ppo", device)       # TrainResult(model, log, episodes)
cfg = PPOConfig(total_steps=1_000_000, lr=1e-4)    # lr thấp hơn cho giai đoạn tinh chỉnh
new = train_ppo(cfg, model=old.model, save_path="runs/ppo_cont.pt", device=device)

"Train tiếp" ở đây chỉ nạp trọng số

Thư viện không lưu optimizer, bước hiện tại hay lịch learning rate. Vì vậy khi truyền model=:

  • Optimizer (Adam) bắt đầu lại từ trạng thái trống.
  • PPO: lịch lr chạy lại từ cfg.lr về 0 trong total_steps mới. Nên đặt lr thấp hơn lần đầu.
  • DQN: replay buffer rỗng, learning_starts đếm lại, và epsilon lại bắt đầu từ eps_start = 1.0 (tức agent chơi ngẫu nhiên trở lại!). Hãy đặt eps_start thấp (ví dụ 0.1) khi train tiếp.
  • Đường cong của lần train mới tự bắt đầu lại từ bước 0, nhưng save_run(new, "runs", "ppo") vào đúng tên run cũ sẽ nối episodes và log vào sau run cũ (bước env được cộng offset nên biểu đồ liền mạch). Muốn tách riêng thì lưu ra tên khác, hoặc truyền append=False để ghi đè.

Chạy nhiều seed hoặc nhiều cấu hình

Một lần chạy RL rất nhiễu: cùng cấu hình mà khác seed có thể khác nhau xa. Muốn kết luận "cấu hình A tốt hơn B", chạy mỗi cấu hình với ít nhất 3 seed (--seed 0/1/2).

for s in 0 1 2; do
  python -m pacman_rl train ppo --seed $s --name ppo_base_s$s
  python -m pacman_rl train ppo --seed $s --name ppo_c2_0.02_s$s --set c2=0.02
done

foreach ($s in 0,1,2) {
  python -m pacman_rl train ppo --seed $s --name "ppo_base_s$s"
  python -m pacman_rl train ppo --seed $s --name "ppo_c2_0.02_s$s" --set c2=0.02
}

from pacman_rl import PPOConfig, train_ppo, save_run, get_device

def main():
    device = get_device()
    for seed in (0, 1, 2):
        for tag, kw in {"base": {}, "c2_0.02": {"c2": 0.02}}.items():
            cfg = PPOConfig(seed=seed, **kw)
            result = train_ppo(cfg, device=device)
            save_run(result, "runs", f"ppo_{tag}_s{seed}")

if __name__ == "__main__":
    main()

Rồi vẽ chung các run để so sánh (nhãn là tên run): python -m pacman_rl plot ppo:ppo_base_s0 ppo:ppo_c2_0.02_s0. Chạy lần lượt (không song song) vì mỗi lần train đã dùng hết CPU.

Chọn cỡ theo máy

n_envs và CPU

Mặc định 16 phù hợp với CPU nhiều nhân. Máy yếu hơn:

MáyGợi ý
8 nhân trở lên, RAM 16 GBGiữ nguyên n_envs=16
4 đến 6 nhân--set n_envs=8 n_steps=256 (PPO giữ batch 2,048)
Rất yếu hoặc kiểm tra nhanh--set n_envs=4 n_steps=512. n_envs luôn phải chẵn.

Đây là gợi ý theo nguyên tắc chung chứ không phải kết quả đo trên mọi máy. Cách tin cậy nhất là chạy ngắn và so steps/s.

Bộ nhớ

Thành phầnCông thứcMặc định
Replay buffer DQN (RAM)buffer_size × 7,080 byte≈ 1.4 GB (200,000)
Rollout PPO (thiết bị tính toán)n_steps × n_envs × 28,224 byte≈ 58 MB
Process envn_envs process con16

Muốn buffer lớn hơn (ví dụ 1,000,000 mẫu) thì cần khoảng 7 GB RAM trống, tính trước khi tăng buffer_size.

Thời gian dự kiến

Tốc độ thật phụ thuộc máy. Trên máy phát triển dự án (RTX 3070 Ti Laptop), PPO đo được khoảng 2,400 đến 3,400 steps/s và DQN khoảng 600 đến 1,900 steps/s (DQN dao động theo RAM trống). Suy ra:

RunBướcƯớc lượng (trên máy đó)
PPO mặc định2,000,000khoảng 10 đến 14 phút
DQN mặc định10,000,000khoảng 1.5 đến 4.5 giờ

Hãy coi đây là bậc độ lớn để lên kế hoạch, và đo lại bằng một lần chạy ngắn trên máy của bạn.
