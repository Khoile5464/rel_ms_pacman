Hướng dẫn

Đánh giá và xem agent chơi

Điểm in ra lúc train chưa phải thước đo cuối cùng. Đánh giá chạy riêng, theo cách công bằng và lặp lại được: game đầy đủ 3 mạng, điểm thật, seed cố định.

Vì sao cần bước đánh giá riêng

  • Lúc train, agent chơi bằng policy đang thay đổi, và còn có khám phá (lấy mẫu hoặc epsilon cao).
  • Env lúc train dùng EpisodicLife (mất mạng = hết episode); đánh giá chạy trọn ván 3 mạng như game thật.
  • Điểm đánh giá là điểm thật, không qua reward_fn, nên so sánh được giữa các cấu hình reward khác nhau.

Chấm điểm bằng dòng lệnh

python -m pacman_rl eval ppo --episodes 20
python -m pacman_rl eval ppo --episodes 20 --greedy
python -m pacman_rl eval dqn --name dqn_seed1 --eps 0.01

PPO trên 20 ván: mean <trung bình> | std <độ lệch chuẩn> | max <ván cao nhất>
Điểm: [<điểm từng ván>]

Tùy chọn đầy đủ ở CLI: eval.

Chấm điểm trong Python

from pacman_rl import load_run, ppo_policy, dqn_policy, evaluate, random_baseline, get_device
from pacman_rl.plotting import plot_eval

device = get_device()
ppo = load_run("runs", "ms_pacman_ppo", "ppo", device)
dqn = load_run("runs", "ms_pacman_dqn", "dqn", device)

results = {
    "Random": random_baseline(5),
    "PPO": evaluate(ppo_policy(ppo.model, device), n_episodes=10),
    "DQN": evaluate(dqn_policy(dqn.model, device, eps=0.05), n_episodes=10),
}
plot_eval(results, save_path="eval.png")      # in bảng mean/std/max và vẽ boxplot

random_baseline cho biết agent không học gì đạt bao nhiêu điểm. Nếu agent của bạn không hơn nó rõ rệt thì chưa học được gì đáng kể.

Các lựa chọn khi chấm điểm

Số ván

Điểm mỗi ván dao động mạnh (độ lệch chuẩn thường lớn so với trung bình). 10 ván cho cảm nhận ban đầu; muốn so sánh hai agent gần nhau thì dùng 30 ván trở lên và nhìn cả std, đừng chỉ nhìn trung bình.

Seed

evaluate dùng seed cố định: ván thứ i dùng seed 1000 + i. Mọi agent được chấm trên cùng các tình huống xuất phát, nên so sánh công bằng. Đổi seed=... nếu muốn một bộ ván khác.

Seed cố định chưa phải kết quả cố định

Seed chỉ cố định phía env. PPO mặc định lấy mẫu action, nên lần chạy sau cho điểm hơi khác. Nếu cần đúng từng con số (ví dụ viết báo cáo), dùng greedy=True / --greedy: khi đó không còn yếu tố ngẫu nhiên nào ở phía policy.

PPO: lấy mẫu hay greedy

  • Lấy mẫu (mặc định): chơi đúng như lúc train. Phản ánh policy đã học.
  • Greedy: luôn chọn action có xác suất cao nhất. Thường ổn định hơn nhưng đôi khi kẹt lặp một chuyển động.

Hãy thử cả hai và báo cáo rõ bạn dùng cái nào.

DQN: epsilon khi chơi

Mặc định eps=0.05. Greedy tuyệt đối (eps=0) có thể làm agent kẹt; một chút ngẫu nhiên giúp thoát. Dùng cùng một eps cho mọi lần so sánh.

max_steps

Mỗi ván bị cắt sau max_steps=4500 bước (18,000 frame, khoảng 5 phút game) để tránh chạy vô hạn khi agent kẹt. Agent rất giỏi có thể chạm trần này. Khi đó điểm bị cắt thấp hơn thực tế; tăng max_steps trong Python (CLI chưa có tùy chọn này).

evaluate(act, n_episodes=10, max_steps=20000)

Tự viết policy

Một policy chỉ là hàm act(obs) -> int với obs là np.ndarray uint8 hình (4, 84, 84) (hoặc (12, 84, 84) với model RGB; ppo_policy / dqn_policy tự cho evaluate / watch biết để dựng đúng env). Nhờ vậy bạn có thể đo bất kỳ thứ gì bằng cùng cách:

import random
from pacman_rl import evaluate

def always_right(obs):
    return 2                      # RIGHT

def jittery(obs):
    return random.choice([2, 3])  # RIGHT hoặc LEFT

print(evaluate(always_right, n_episodes=5))
print(evaluate(jittery, n_episodes=5))

Bảng chỉ số action ở Môi trường và các loại điểm. Ví dụ khác: policy từ một mạng khác, tập luật, hoặc ensemble nhiều model (trung bình Q của vài QNetwork).

Xem agent chơi

python -m pacman_rl play ppo --greedy --episodes 3

from pacman_rl import watch, ppo_policy
watch(ppo_policy(ppo.model, device), episodes=2)     # in điểm từng ván

Cần có màn hình (mở cửa sổ game). Quan sát hành vi bằng mắt thường hay lộ ra điều mà số điểm không nói: agent đi vòng vòng, né ma kém, bỏ qua viên năng lượng...

Báo cáo kết quả

Một báo cáo có thể tin cậy cần có: số ván, seed đánh giá, chế độ chọn action (greedy hoặc eps), cả mean lẫn std hoặc boxplot, mốc random_baseline, và nếu có thể, kết quả của nhiều seed train (không chỉ nhiều ván chơi của một model).
