Hợp đồng của một hàm train

Để mọi thứ khác (CLI, vẽ, đánh giá, lưu/nạp) dùng được thuật toán của bạn, hàm train cần tuân thủ:

  1. Chữ ký chuẩn: train_<tên>(cfg=None, *, model=None, save_path=None, device=None, render=False, watch_every=0, watch_episodes=1). Siêu tham số vào cfg (dataclass); các tùy chọn chạy là keyword riêng, vì chúng không đổi kết quả học.
  2. Trả về TrainResult(model, log, episodes).
    • log: dict khóa → list, mọi list cùng độ dài với log["step"] (bước env). Phải có step, pellets, ghosts để các hàm vẽ dùng được.
    • episodes: list (bước env, điểm thật cả ván), lấy từ giá trị scores mà envs.recv(g) trả về.
  3. Dùng PipelinedEnvs: gọi send(g, action) / recv(g) theo mẫu "gửi nhóm này rồi nhận" để giữ pipeline CPU/GPU (xem Env song song và pipeline).
  4. Có trường reward_fn trong config, mặc định log_reward, và gọi cfg.reward_fn(reward) trên reward thật của mỗi nhóm. Đếm sự kiện bằng count_events(reward) trên reward thật.
  5. Có log_every và save_every; ghi rõ đơn vị (update hay bước env) trong comment của trường.
  6. Dọn dẹp: bắt KeyboardInterrupt, envs.close() trong finally, và lưu state_dict vào save_path khi kết thúc.
  7. Mạng phải nhận uint8 hình (B, 4, 84, 84) và tự chia 255 (như hai mạng sẵn có).

Ví dụ: thêm A2C

Khác PPO ở đâu

A2C đơn giản hơn PPO: rollout ngắn (mặc định 5 bước mỗi env), tính return n bước, một lần cập nhật trên rollout đó (không có epoch hay minibatch hay clip). Vì dùng lại ActorCriticCNN và cùng kiểu rollout như PPO, phần lớn mã là sao chép cấu trúc train_ppo rồi thay phần tính loss.

loss = −mean( log π(a|s) · A )  +  c1 · mean( (V(s) − R)² )  −  c2 · mean( H[π] )
với  R_t = r_t + γ · (1 − done_t) · R_{t+1},   A = R − V(s)  (không truyền gradient qua A)

Bước 1. Tạo agents/a2c.py

"""A2C (advantage actor-critic đồng bộ) cho Ms. Pacman: rollout ngắn, một lần cập nhật cho mỗi rollout."""
import time
from dataclasses import dataclass
from typing import Callable

import numpy as np
import torch
import torch.nn as nn
import torch.optim as optim

from ..envs import PipelinedEnvs, count_events, log_reward
from ..evaluation import ppo_policy, watch
from ..models import ActorCriticCNN
from ..utils import get_device, set_seed
from .common import TrainResult


@dataclass
class A2CConfig:
    total_steps: int = 2_000_000
    n_envs: int = 16
    n_steps: int = 5              # bước mỗi env trong một rollout (batch = n_envs x n_steps)
    lr: float = 7e-4
    gamma: float = 0.99
    c1: float = 0.5               # trọng số value loss
    c2: float = 0.01              # trọng số entropy bonus
    max_grad: float = 0.5
    seed: int = 0
    log_every: int = 500          # in log mỗi bao nhiêu update
    save_every: int = 5000        # lưu checkpoint mỗi bao nhiêu update (khi có save_path)
    reward_fn: Callable = log_reward   # reward thật (mảng n_envs) -> reward dùng để học


def train_a2c(cfg=None, *, model=None, save_path=None, device=None, render=False,
              watch_every=0, watch_episodes=1):
    """Train A2C, trả về TrainResult(model, log, episodes). Tham số giống train_ppo."""
    cfg = cfg or A2CConfig()
    device = device or get_device()
    set_seed(cfg.seed)
    envs = PipelinedEnvs(cfg.n_envs, render=render)
    obs = torch.as_tensor(envs.reset(seed=cfg.seed), device=device)

    model = (model or ActorCriticCNN(envs.n_actions)).to(device)
    optimizer = optim.RMSprop(model.parameters(), lr=cfg.lr, alpha=0.99, eps=1e-5)

    n_envs, n_steps = cfg.n_envs, cfg.n_steps
    batch = n_envs * n_steps
    n_updates = cfg.total_steps // batch
    B_obs = torch.zeros((n_steps, n_envs, 4, 84, 84), dtype=torch.uint8, device=device)
    B_act = torch.zeros((n_steps, n_envs), dtype=torch.long, device=device)
    B_rew = torch.zeros((n_steps, n_envs), device=device)
    B_done = torch.zeros((n_steps, n_envs), device=device)

    ep_log = []
    log = {"step": [], "ent": [], "v_loss": [], "pg_loss": [], "pellets": [], "ghosts": []}
    global_step, t0, n_pellet, n_ghost = 0, time.time(), 0, 0
    print(f"A2C: {n_updates} updates x {batch} mẫu = {n_updates * batch:,} bước, {n_envs} env song song")

    def launch(t, g):
        sl = envs.slices[g]
        a, _, _ = model.act(obs[sl])
        B_obs[t, sl], B_act[t, sl] = obs[sl], a
        envs.send(g, a.cpu().numpy())

    try:
        for update in range(n_updates):
            # ---- Pha 1: thu rollout (giống PPO: 2 nhóm env xen kẽ với GPU) ----
            for g in range(envs.G):
                launch(0, g)
            for t in range(n_steps):
                for g in range(envs.G):
                    sl = envs.slices[g]
                    next_obs, reward, done, scores = envs.recv(g)
                    global_step += envs.gs
                    ep_log.extend((global_step, s) for s in scores)
                    p, gh = count_events(reward); n_pellet += p; n_ghost += gh
                    B_rew[t, sl] = torch.as_tensor(cfg.reward_fn(reward), device=device)
                    B_done[t, sl] = torch.as_tensor(done, dtype=torch.float32, device=device)
                    obs[sl] = torch.as_tensor(next_obs, device=device)
                    if t + 1 < n_steps:
                        launch(t + 1, g)

            # ---- Pha 2: return n bước, nối vào giá trị của critic ở cuối rollout ----
            with torch.no_grad():
                ret = model(obs)[1]
            returns = torch.zeros_like(B_rew)
            for t in reversed(range(n_steps)):
                ret = B_rew[t] + cfg.gamma * (1.0 - B_done[t]) * ret
                returns[t] = ret

            # ---- Pha 3: một lần cập nhật trên cả rollout ----
            dist, value = model(B_obs.reshape(batch, 4, 84, 84))
            f_ret = returns.reshape(-1)
            adv = (f_ret - value).detach()
            pg_loss = -(dist.log_prob(B_act.reshape(-1)) * adv).mean()
            v_loss = ((value - f_ret) ** 2).mean()
            entropy = dist.entropy().mean()
            loss = pg_loss + cfg.c1 * v_loss - cfg.c2 * entropy

            optimizer.zero_grad()
            loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), cfg.max_grad)
            optimizer.step()

            for k, v in zip(log, [global_step, entropy.item(), v_loss.item(), pg_loss.item(), n_pellet, n_ghost]):
                log[k].append(v)

            if watch_every and global_step // watch_every > (global_step - batch) // watch_every:
                print(f"[watch] step {global_step:,}")
                watch(ppo_policy(model, device), watch_episodes)

            if save_path and (update + 1) % cfg.save_every == 0:
                torch.save(model.state_dict(), save_path)

            if (update + 1) % cfg.log_every == 0 or update == n_updates - 1:
                recent = [r for _, r in ep_log[-20:]]
                print(f"Update {update + 1}/{n_updates} | step {global_step:,} | "
                      f"avg score(20) {np.mean(recent) if recent else float('nan'):.0f} | "
                      f"viên NL {n_pellet:,} | ma {n_ghost:,} | entropy {entropy.item():.3f} | "
                      f"{global_step / (time.time() - t0):.0f} steps/s")
    except KeyboardInterrupt:
        print(f"Dừng sớm ở step {global_step:,}")
    finally:
        envs.close()
    if save_path:
        torch.save(model.state_dict(), save_path)
    return TrainResult(model, log, ep_log)

Những điểm đáng chú ý trong mã

  • Dataclass config có reward_fn, log_every, save_every như hợp đồng. Giá trị mặc định (lr 7e-4, n_steps=5, RMSprop) lấy theo thiết lập A2C thông dụng trên Atari.
  • launch và vòng thu rollout y hệt PPO (nhưng không cần B_logp và B_val, vì A2C tính lại log-prob và value ngay lúc cập nhật).
  • Return n bước nối vào model(obs)[1], giá trị critic của quan sát cuối rollout.
  • Chỉ một lần backward trên toàn rollout (batch n_envs × n_steps = 80 với mặc định). adv được detach() để gradient của policy không chảy vào critic qua advantage.
  • Log có step, pellets, ghosts (bắt buộc) và thêm ent, v_loss, pg_loss. Dùng khóa ent để biểu đồ entropy mặc định của plot_training cũng hiển thị cho A2C.
  • Khi xem (watch_every) dùng ppo_policy vì A2C dùng cùng mạng actor-critic.

def _policy(args, model, device):
    from .evaluation import dqn_policy, ppo_policy
    if args.algo == "dqn":
        return dqn_policy(model, device, eps=args.eps)
    return ppo_policy(model, device, greedy=args.greedy)       # PPO, A2C: mạng actor-critic

Biến thể nhỏ: Double DQN bằng một cờ

Double DQN chỉ khác DQN gốc ở cách tính mục tiêu: chọn action bằng mạng chính, nhưng đánh giá giá trị bằng target network. Việc này chống ước lượng Q quá cao. Không cần file mới.

Sửa agents/dqn.py

Thêm trường vào DQNConfig (giữ mặc định False để hành vi cũ không đổi):

    max_grad: float = 10.0
    double: bool = False          # True: Double DQN (chọn action bằng mạng chính, đánh giá bằng target)

Thay dòng tính mục tiêu y = r + cfg.gamma * (1 - d) * q_target(s2).max(1)[0] bằng:

                        if cfg.double:
                            a2 = q(s2).argmax(1, keepdim=True)
                            next_q = q_target(s2).gather(1, a2).squeeze(1)
                        else:
                            next_q = q_target(s2).max(1)[0]
                        y = r + cfg.gamma * (1 - d) * next_q

Đoạn này nằm trong khối with torch.no_grad(): sẵn có.

Chạy

python -m pacman_rl train dqn --set double=1 --name dqn_double_s0

--set ép kiểu theo kiểu của giá trị mặc định; với trường bool, dùng 1 hoặc 0 (không dùng true/false). Cả hai chế độ (double=1 và double=0) đã được chạy thử và cho ra log hợp lệ.

Nhớ cập nhật tài liệu

Thêm một khối tham số double vào DQNConfig (bảng tóm tắt, và một mục theo mẫu <section class="param">) và bỏ dòng "không phải Double DQN" ở mục "Những thứ cố định" cùng trang DQN.

  • Chạy ngắn bằng CLI thành công: train, eval, plot (và play nếu có màn hình).
  • Log có step, pellets, ghosts, cùng độ dài; load_run nạp lại được run vừa lưu.
  • Ctrl+C giữa chừng vẫn lưu được kết quả.
  • Không import torch trong envs/.
  • Test mới trong tests/ pass: xem Quy ước, test, viết docs.
  • Docs đã cập nhật: trang tham chiếu config, cột "Một dòng" trong bảng tóm tắt, và nav.js nếu thêm trang.
