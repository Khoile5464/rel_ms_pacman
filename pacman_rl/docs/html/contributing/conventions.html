Quy ước, test, viết docs

Những quy ước giúp mã mới trông và hoạt động như mã sẵn có, cách chạy test, và cách viết hay sửa chính bộ tài liệu này.

Quy ước viết code

  • envs/ không import torch và không import từ module nào có torch. Lý do ở Kiến trúc.
  • Config là dataclass chỉ chứa siêu tham số; tùy chọn chạy (model, save_path, device, render...) là keyword của hàm train.
  • Hàm train in log bằng print, không dùng tqdm, để đọc được cả trong notebook và terminal.
  • Comment và docstring bằng tiếng Việt, theo phong cách notebook gốc. Comment giải thích vì sao hoặc nêu đơn vị, không lặp lại điều code đã nói.
  • Đơn vị rõ ràng: mọi tham số tính theo "update" hay "bước env" phải ghi trong comment của trường (xem log_every của PPOConfig và DQNConfig).
  • Giữ hành vi mặc định khi thêm tính năng: trường mới phải có giá trị mặc định bảo toàn kết quả cũ.
  • Đặt hàm ở cấp module (hoặc dùng partial) thay vì lambda khi hàm cần đi qua process con hay được ghi lại.

In tiếng Việt trên console Windows

Console Windows mặc định dùng cp1252 và không in được tiếng Việt: gọi train_ppo(...) trong một script có thể dừng với UnicodeEncodeError. Dòng lệnh python -m pacman_rl đã tự đổi sang UTF-8 (cli.main), notebook thì không bị. Với script riêng, chạy bằng python -X utf8 script.py hoặc đặt biến môi trường PYTHONUTF8=1.

Test

Test nằm ở tests/, không cần emulator nên chạy nhanh. Cần cài pytest (một lần):

pip install -e "pacman_rl[dev]"      # hoặc: pip install pytest
pytest pacman_rl                     # chạy từ thư mục rel_ms_pacman/

Test hiện có trong tests/test_core.py:

TestKiểm tra
test_log_reward_and_eventslog_reward đúng công thức; count_events đếm đúng viên năng lượng và ma
test_network_shapesHình dạng đầu ra của ActorCriticCNN (forward và act) và QNetwork
test_replay_buffer_stacks_within_episodeChồng 4 frame lặp frame đầu episode, bắt đầu mới ở episode mới, không trộn giữa các env
test_save_load_run_roundtripsave_run rồi load_run trả về đúng log, episodes và trọng số

Viết test mới

  • Test phần thuần: biến đổi reward, hình dạng tensor, logic buffer, lưu/nạp. Tránh gọi make_env hay train_* (cần emulator, chậm).
  • Dùng dữ liệu nhỏ có đáp án tính tay được (như test buffer: frame ghi ở bước t của env e có giá trị 10e + t).
  • Dùng fixture tmp_path của pytest cho mọi thứ ghi ra đĩa.
  • Thêm test khi sửa lỗi, để lỗi đó không quay lại.
import numpy as np
from pacman_rl.envs import log_reward

def test_log_reward_is_monotonic():
    r = log_reward([0, 10, 50, 200, 1600])
    assert np.all(np.diff(r) > 0)

Ngoài test tự động, mọi thay đổi chạm vào vòng train nên có một lần chạy ngắn bằng CLI (train, eval, plot) để xác nhận cả chuỗi vẫn hoạt động.

Viết và sửa tài liệu này

Tài liệu là các file HTML tĩnh trong docs/html/, không cần công cụ build. Mở index.html bằng trình duyệt là xem được (kể cả khi mở thẳng file). Thanh bên, mục lục trang, tìm kiếm, nút copy và chuyển sáng/tối đều do assets/docs.js dựng, nên mỗi trang chỉ cần nội dung.

Thêm một trang

  1. Sao chép một trang gần giống

    Ví dụ guides/evaluation.html. Sửa <title>, h1, nội dung.

  2. Đặt data-root và data-page ở thẻ <body>

    <body data-root="../" data-page="guides/ten-trang.html">

    data-root là đường dẫn tương đối từ trang về docs/html/ (./ cho trang gốc, ../ cho trang trong thư mục con). data-page khớp với path trong nav.js.

  3. Khai báo trong assets/nav.js

    { path: "guides/ten-trang.html", title: "Tên hiển thị" }

    Thứ tự trong nav.js cũng là thứ tự "Trước/Tiếp" ở cuối trang.

  4. Cho mọi h2/h3 một id duy nhất

    Id dùng cho mục lục bên phải, neo liên kết và tìm kiếm.

  5. Sinh lại chỉ mục tìm kiếm và kiểm tra liên kết

    cd pacman_rl/docs/html
python build_search_index.py     # ghi assets/search-index.js; cảnh báo nếu tiêu đề thiếu id
python check_links.py            # báo link và neo (#...) bị gãy

Link mở code trong VS Code

Bạn không cần viết thẻ <a> nào. Khi docs được mở bằng file://, docs.js tự biến mỗi <code> inline có nội dung đúng bằng một tên có trong assets/source-index.js thành link vscode://file/<đường dẫn>:<dòng>. Tên được nhận gồm:

  • hàm và lớp ở cấp module (train_ppo, PipelinedEnvs), hằng viết hoa (ALGOS, N_ACTIONS);
  • đường dẫn file tính từ src/pacman_rl/ (agents/ppo.py, cli.py);
  • trên trang ppo-config.html và dqn-config.html, tiêu đề của mỗi khối tham số được nối với trường dataclass tương ứng (nhờ thuộc tính data-cfg ở <body>).

source-index.js do build_search_index.py sinh bằng cách quét src/pacman_rl/. Sau khi code đổi (số dòng dịch), chạy lại script đó để link trỏ đúng dòng. Code trong khối <pre> và chữ nằm trong một link có sẵn thì không bị biến thành link. Muốn tránh một chữ bị tự link, bọc nó trong <a href="#"> hoặc đổi cách viết.

Phong cách viết

  • Bám theo code: mọi con số mặc định và công thức phải khớp mã nguồn. Sửa code thì sửa docs trong cùng thay đổi.
  • Nói rõ mức độ chắc chắn: phân biệt "đã đo/đã chạy" với "kinh nghiệm chung". Đừng đưa số liệu không có thật.
  • Đơn vị đi kèm con số: bước env, update, byte, giây.
  • Một ví dụ chạy được đáng giá hơn một đoạn mô tả. Trước khi đưa code vào tài liệu, hãy chạy nó.

Danh sách kiểm tra khi gửi thay đổi

  • Hành vi mặc định không đổi (trừ khi chủ ý, và khi đó ghi rõ).
  • pytest pacman_rl pass; thêm test cho phần mới.
  • Chạy ngắn bằng CLI: train, eval, plot.
  • envs/ vẫn không import torch.
  • Tài liệu cập nhật; build_search_index.py và check_links.py chạy sạch.
